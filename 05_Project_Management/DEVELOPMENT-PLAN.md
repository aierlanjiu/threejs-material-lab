## 一、这一段的原则（先对齐，再干活）

### 产品定位（已由 zedpapa 校准）

> **这不是素材生产工厂，是一台个性化音乐氛围装置。**
> 目的是创造令用户身心愉悦、视觉震撼的个性化定制音乐流媒体体验，并能把这段体验以视频形式复制分享给他人。

### 由此推出的两条第一性原理

**1. 价值单位是「分钟」，不是「块」。**

> 装置的价值 = 用户愿意在里面待多久 × 被打动多少次。
> 所以它只有一个敌人：**出戏**。

这直接决定优先级：**"不让用户出戏"永远优先于"加一个好看的东西"**。

**2. 愉悦靠持续，震撼靠单点，两者对工程的要求相反。**

| | 愉悦（持续） | 震撼（单点） |
| --- | --- | --- |
| 靠什么成立 | 全程**不出事** | 开场 3 秒**必须发生一次** |
| 谁在消费 | 创作者自己（在场） | 观众（看视频） |
| 崩掉的后果 | 装置退化成网页 | 划走，分享链路断掉 |

### 操作纪律

- **出戏四源排序**：① 不流畅 ② 不确定感 ③ 没有回响 ④ 重复疲劳。所有排序按它来。
- **能用实测就不用推演**：`window.luDiagnostics` 已能读到真实运行时状态，量出来再动手。
- **每次改动配一条回归**，藏在测试注释里的坑不许再踩第二次（见交接文档第 9 节）。
- **双副本必须同哈希**。

### 当前已验证的地基（不要重复造）

- 主画面几何契约 + 精确 OBB 避让求解器（3150 帧 0 相交）
- 静息待机态（没音乐时装置自主呼吸）
- 入场错时（对角扫掠，稀疏内容时角色第一拍）
- 角色默认在场 + 启动预热
- 自定义图集盲盒（稳定哈希抽取）
- 4 条可用回归

## 三、P1：消灭出戏（最高优先，与审美无关）

### P1-1. 卡顿治理 ★ 最高优先

**为什么第一**：氛围装置里一次卡顿就是出戏；更要命的是**录制是实时采集**（`canvas.captureStream(60)` + `MediaRecorder`），掉帧会直接写进母带，而母带是要发出去给人看的。

**已知事实**：
- 基线真实音频播放 180 帧：平均 12.6ms、**P95 26.1ms**、最大 26.2ms —— 60fps 预算是 **16.7ms**，P95 已越线。
- `renderer.setPixelRatio(Math.min(devicePixelRatio, 2))`（`:2413`）叠加后处理 4× MSAA。Retina 下像素量翻倍，这是首要嫌疑。
- 录制码率固定 16Mbps（`:4341`），与分享体积直接冲突（16Mbps × 3 分钟 = 360MB，而微信聊天上限约 25MB）。

**动作**：
1. 先用 `luDiagnostics` 挂一个帧时直方图，跑 5 分钟真实演奏，量出 `hitchRate`（>16.7ms 占比）与 `hitchCluster`（连续掉帧最长）。
2. 定位主因（像素比 / 阴影贴图重算 / 每帧材质重建 / 避让求解器），**量出来再改**。
3. 录制链路面向分享重定标：**9:16 竖屏 + 30fps + 6Mbps 档位**（30fps 同时把帧预算从 16.7ms 放宽到 33.3ms）。
4. 可选优化：把不可避免的掉帧**对齐到鼓点**——卡在鼓点上感知几乎不可见，卡在乐句中间立刻出戏。

**验收**：连续 5 分钟演奏 `hitchRate = 0`；导出一段 60 秒可被微信直接发送（≤ 30MB）的竖屏视频。

### P1-2. 沉浸模式仪式化

**为什么**：`setImmersive()` 已经存在（`F` 键 / 右上角按钮），但被当成逃生口。用户需要清晰的**两段式**：

```
第一段 · 造境   选音乐 → 选角色/图集 → 调整（可跳过）
      ↓  一个明确的「开始」：画面渐暗、界面退去、镜头就位
第二段 · 在场   什么都不用做，装置自己演
```

现在两段糊在一起——用户可以随时拨任何滑块，**装置从不宣布"演出开始"**。没有开始就没有在场。

**验收**：从点开到进入"在场"不超过 3 步；进入后有明确的视觉收束（界面确实退去）。

### P1-3. 收尾与 session 曲线

- **音乐结束时装置做什么？** 现在只有能量按 `exp(-6.32·dt)` 衰减，**能量衰减 ≠ 体验收尾**。应该缓缓退回静息态，而不是"啪"地僵住。这一秒决定整段体验是被记住还是被忘掉。
- **`isChoreographyShow` 目前是匀速轮转**（`morphIntervalBeats = 16`），三段之后用户就学会了。需要一条曲线：开场震撼 → 中段平稳 → 一次转折 → 缓慢落下。

**验收**：20 分钟 session 内无明显"我学会了"的时刻；结束时画面有落回而不是僵住。

## 四、P2：结构改造（决定后面还能不能快起来）

### P2-1. 四轴正交化

现在 `state` 有 60+ 字段互相耦合。建议冻结为四轴：

```
① Material  材质光学  → 预算级（决定渲染成本与光学正确性）
② Form      形状布局  → 结构级（决定碰撞预算、格距）
③ Program   时间程序  → 帧级（什么时候变、变多少）
④ Content   信息内容  → 内容级（每格承载什么）
```

**其中 ③④ 最乱**：`contentMode` 把"内容类型"与"排布方式"混在一起（`avatarDist` / `imageDist` / `layerMode` 各写一遍）；图集盲盒与角色盲盒是两套独立机制。**要混排（用户照片 + 官方角色同场）必须统一成一条内容源抽象。**

**验收**：给定同一份配置，画面由配置唯一决定；新增一种内容源只需实现一个接口，不改主循环。

### P2-2. 音乐从"传感器"升级为"谱面"

现在是实时 FFT，音乐是不可预知的时间轴——无法编排"副歌进场时全阵列翻转"，因为副歌何时来只有播到才知道。

**动作**：先做**段落级**（离线分析段落与关键瞬态，生成时间轴），不要一上来做整曲编排。

### P2-3. 确定性（服务于"体验可复制"）

用户选的是"把自己这段演奏录下来发给朋友"，那么**同一次演奏必须能被完整重放**。现在 `state.time` 由真实时间驱动，同一参数两次录制结果不同。

**动作**：单一时间源 + 状态指纹。**注意排序**：这件事的价值在 P2，而 P1-1 的卡顿是当下最痛的——**先 P1 再 P2**。

## 五、P3：玉牌（薄板翻转）形态

**优先级最低，但推导已完成，随时可用**（详见交接文档第 7 节）：

- 形态 `1×1×0.35`；不能靠 `scale.z` 做薄（会毁掉倒角）
- 45° 抬升解析解 `|sin 2θ|·(√(1+d²)−1)/2`，d=0.35 时峰值 **0.0297**
- 横向不必加宽格距（支持函数峰值 0.5270 < 现行包络）
- 卡点在包络补偿会在翻转中途把牌缩到 61%
- 接触阴影要跟着朝向调制

**为什么排最后**：它服务于"抚慰节律"，而 P1 三项服务于"不出戏"。**地基没稳之前不要盖楼。**
