### 3.4 渲染与时钟事实

- Three.js r166.1；WebGLRenderer；ACESFilmicToneMapping；像素比上限 1.5；现有阴影贴图为 512×512。
- 已有玻璃阶梯、投影、多个追光、透明角色和粒子层，透明采样和屏幕覆盖成本不能只用三角面数量衡量。

- `setTheme()` 与 `setLayout()` 当前有联动重建和异步背幕加载，扩展时必须检查重复实例、过期回调与释放顺序。

## 5. 场景设计提案

### 5.1 视觉层级

从前到后保持：角色与演奏 → 棱镜舞台 → 精致演出设备 → 梦幻侧景 → 背幕。

新增浮岛只承担舞台两侧或后景的装饰，顶部灯具与少量漂浮物补全上方空间。角色面部、手部/乐器、歌词、底部播放器、翼效展开区与焰火喷口属于保护区。

演出设备采用炭灰箱体、细金属边、可读的喇叭与灯头结构；梦幻部分用有体积的石岛、有机植物、局部透光叶片与晶体。不能把全部物件统一做成高透射玻璃，也不能依靠铺满粒子制造梦幻感。

### 5.2 共用设备模型清单

| 资产 ID | 制作内容 | 现有基础 | 提议实例上限，横向/竖向 |
| --- | --- | --- | --- |
| `speaker-stack` | 倒角箱体、双单元喇叭、金属边与少量节拍灯 | 精修当前 speaker | 4 / 2 |
| `floor-monitor` | 楔形返听、低对比网面与侧边细节 | 精修当前 monitor | 2 / 2 |
| `moving-head` | 灯座、灯轭、灯头、镜片和固定转轴 | 精修现有灯架灯具；只为已有灯位增加结构 | 8 / 6，若预算不允许保留原数量并简化几何 |
| `truss-detail` | 横梁节点、连接套和必要的支撑细节 | 复用 truss 和杆件批处理 | 固定，不新增第二套灯架 |

这些是共享模板，不是为每个主题分别建模。实例数量最终以构图与预算为准；新增静态网面应使用轻几何或已有材质表达，避免用成百上千独立小孔建模。

### 5.3 三个主题的梦幻装饰

| 主题 | 核心侧景提案 | 小型点缀 | 与现有元素的关系 |
| --- | --- | --- | --- |
| 海贼王 | 两座海礁浮岛，青蓝透光珊瑚、卷曲海草或少量海晶 | 暖色航灯与小型漂浮水滴 | 保留帆幕、海面背幕，避免新建大船遮住演员 |
| 龙珠 | 两座悬浮岩岛，青绿发光草与少量琥珀晶体 | 小型轨道环或能量石 | 保留现有七星球拱架，不再堆第二组七颗球 |
| 火影 | 两座苔石浮岛，发光竹叶/蕨叶、小型暖灯 | 少量叶片或微型纸灯 | 保留鸟居与灯笼，不新增第二座鸟居 |

每个主题共用浮岛基础工艺，但植物轮廓、点缀和表面处理分别设计；只有换色不算完成三主题差异。

提议先按每主题「2 个岛、每岛 1 组主要植物/晶体、最多 2 个后景点缀」起步。桌面可以完整展示，手机根据保护区降密度。精确数量和造型属于审阅及设计稿阶段待确定参数。

## 6. 三维资产制作与交付

推荐先使用现有 Three.js r166.1 可支持的程序化几何和材质，生成真实可旋转、有侧面与厚度的 `THREE.Group/Mesh`，而不是把新增物体烘成一张背景图。

- 设备采用可复用的倒角箱体、圆柱、有限段数的圆环和灯轭；植物采用少量有厚度/可双面显示的叶片，依实际屏幕大小确定细分。
- 浮岛使用可控的低面数轮廓与顶部植被层；底部呈锥状/悬浮石体，不采用高面数扫描矿石。
- 重复晶体、叶片、设备单元合并或实例化，避免每个细节都独占材质和 draw call。
- 核心场景几何与配置可编辑、可重复生成；随机分布采用固定种子，不能在每次切主题或 seek 时重新随机。
- 如评审后选用 Blender/GLB，需保留制作源文件、根节点、pivot、比例、材质分组、授权和压缩前后对照，并证明 r166.1 兼容。GLB 导出属于可选交付，不默认引入新的生产链路。
- SimReady 与其他第三方模型只作为可选选型参考。本提案不依赖下载这些模型，也不能把搜索结果或一个模型文件名当作已验证可用资产。

提议交付：共享设备模板、三个主题装饰包、资产清单与数量/几何统计、横竖场景预览、录制样片、验证记录。制作源代码本身作为程序化资产源，不另行要求不可编辑的截图替代模型。

## 7. 布局、保护区与取景

### 7.1 世界坐标约定

沿用 X 左右、Y 向上、Z 前后的现有坐标。设备落地位置通过 `stageHeightAt()` 求值，禁止手工猜台阶高度。装饰锚点由 `stageSpec(narrow)`、主题与质量档决定，不能写两套与当前舞台脱节的尺寸常数。

初始设计约束：岛屿主体集中在两侧后半区；顶部漂浮物放到演员最高点之上；正中与前排尽量留空。植物和晶体的合成轮廓以演员身高为参照，常态单组高度建议约为演员的 0.35–0.65 倍；该比例是提案，需用实际画面验证。

### 7.2 屏幕空间约定

世界坐标布局后必须用当前 camera 投影检查，而不是通过增加镜头距离强行装下新增装饰。

保护区至少包括：

1. 当前队形及手动位置中每名角色的投影矩形，面部和乐器区域增加安全边距。
2. 现有翼效展开投影区域及前排焰火喷口/主要喷发通道。
3. 歌词、顶部菜单与底部播放器/谱窗的实际覆盖范围；结合场景已有 safeTop/safeBottom，必要时由现有 UI 提供边界。
4. 录制时的逻辑尺寸和输出尺寸，不能把 renderer 物理像素直接当 CSS 像素。

保护优先级：角色/歌词/控制 → 既有翼效与焰火 → 新增装饰。冲突时依次移到后景、减小、隐藏可选点缀，最后保留单组侧景；不缩小角色、不挤压播放器，也不新增供用户自行排障的控制面板。

手机不得仅按桌面 x 坐标同比缩放；需针对窄竖构图安排后上方角落、低密度植物与少量装饰。不要按每一帧的微小投影抖动反复显隐，使用保守安全边界及稳定的布局选择；连续镜头期间允许平滑淡出，暂停/seek 必须能确定性重建。

## 8. 音乐响应与状态规则

新增模块只消费既有歌曲 `time` 和灯光/节拍状态，不分析新音频、不改变音轨、不创建自己的 `requestAnimationFrame`。

| 对象 | 常态响应提案 | 强拍/高潮响应 | 限制 |
| --- | --- | --- | --- |
| 浮岛 | 以歌曲 time 计算极轻的上下呼吸 | 振幅小幅提升 | 不承载角色；不做大幅摇摆与突跳 |
| 发光植物 | 低频亮度呼吸，叶尖轻摆 | drums/downbeat 带来短包络 | 不全屏闪烁，不能逐帧随机换色 |
| 晶体/能量石 | 轻缓转动或局部高光 | bass/beat 增加内部发光 | 不为每颗晶体新增实时灯 |
| 音箱细灯 | beat/downbeat 驱动灯条 | 高潮适度提亮 | 箱体和喇叭不夸张伸缩，不改发声逻辑 |
| 灯具 | 复用已有追光方向与颜色 | 小幅灯头运动 | 不另起一套冲突的灯光控制器 |

动画参考表达式：`position = restPosition + amplitude * sin(songTime * frequency + fixedPhase)`。具体幅度、周期需在设计稿中给出，再依据画面和性能修订。

状态规范：

- 播放：从现有 `frame.time` 连续采样。
- 暂停：时间不变则画面保持，不继续漂浮、旋转或呼吸。
- 跳转：相同输入时间、主题、布局和设置应得到相同姿态；不积累 `deltaTime`。
- `effects=off`：保留静态模型，关闭新增动态与节拍发光；该策略针对新增资产，不重定义既有系统的其他行为。
- `prefers-reduced-motion: reduce`：新增模型使用稳定姿态和固定照明，不保留悬浮/旋转/脉冲。
- `effects=preview`：遵循已有预览状态，强度仍须受保护区和亮度上限约束。
- 切主题、切歌、横竖切换：先更新配置，下一次由当前歌曲时间重建，不从零启动动画。
- 歌曲结束、退出模式：采用上层已有生命周期与时间，不在隐藏页面持续更新新内容。
- 导出：从已有录制/`renderPromoFrame()` 输入采样，同一时间应与交互页面一致；离线采样结果不能替代实际有声录制验证。

注意：当前 `theatre.update()` 只直接接收 `time/fx/reduced/lighting/viewportHeight/rows`，没有独立 `effectsMode` 参数。实现时必须明确传递该模式；不能看到 `fx.intensity===0` 就错误判断为「关闭特效」。

### 9.2 接口草案

```js
// 提议接口，不是当前已有实现。
createConcertProps(parent, { palette, lightTexture })
// 返回：
{
  configure({ theme, narrow, quality }),
  update({ time, lighting, effectsMode, reduced, camera, viewport, protectedZones }),
  diagnostics,
  dispose()
}
```

`configure()` 相同配置必须幂等。主题、横竖布局或质量档真正变化时才调整资源；逐帧 update 只更新变换/少量 uniform，不新建 geometry/material/texture。

`band-stage.js` 当前接口可向后兼容地增加最后一个 context 参数，或通过局部构造参数提供上下文；先核对两处入口的调用方，再确定唯一方案。effectsMode 应沿当前 scene/update 的 settings 传入，不修改设置存储协议。

### 9.3 生命周期与失败隔离

- 新模块独占的 geometry/material/texture 才由它 dispose；借用的环境贴图、公共 glow texture、舞台材质不得重复释放。
- 共享几何和材质用集合或资源池统一释放；切主题后不残留旧岛屿、旧植物和失效引用。
- 当前 setTheme/setLayout 的联动重建需沿用或补充有效的 generation/revision 检查，确保异步背幕完成时不会重复插入装饰。
- 普通 update 不做全树清空/重建；场景外部 dispose 不能和子模块重复释放同一批资源。
- 资产异常时保留既有舞台和原角色，输出可定位诊断；不得用吞掉所有异常来假装正常。
- 本轮优先程序化资产，避免引入网络加载和大量外部纹理；若改用外部资产，先明确包内相对依赖、超时/重试、缓存和失败回退。
