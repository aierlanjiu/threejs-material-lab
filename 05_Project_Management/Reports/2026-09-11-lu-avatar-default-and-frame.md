# 角色默认在场 + 取景与 FOV 范围调整

Agent: 大江南（DSH 会话）· 2026-09-11

## 背景

前两轮完成静息待机态与入场错时后，剩余的结构性错位是：**个性化资产（角色）默认不出场**。默认仍是"纯材质"模式的水晶方阵，用户必须先翻到检查器第三层、点进"角色"才能看到属于自己的活物——而角色才是这个装置里唯一能产出"这是我的"的东西。

同时，用户实测反馈基础 FOV 视角的范围（20–60）不够用。

## 关键变更

`index.html`（与工程副本 `threejs_material_lab/index.html` 哈希一致）

1. **默认即角色在场**
   - `state.contentMode: 'material'` → `'avatar'`；`#contentModeGroup` 的 active 从"纯材质"移到"角色"；`#avatarPanel` 默认 `display: block`。
   - 启动时**显式点一次火**：角色贴图是启动时同步建的空画布，内容要等 `avatar-bridge.js` 动态 import 完成后才画上去。若不预热，首屏是一张空白脸。预热顺带错时把其余 7 个角色画进面板缩略图（400ms 起、每个间隔 150ms），避免 8 个角色同时抢首帧。
   - 主循环里本就有角色驱动（`contentMode === 'avatar'` 时按 30fps 重绘并更新贴图），默认改为角色模式后，眨眼/注视/呼吸自动生效，无需新增通道。

2. **FOV 范围放宽**：滑块 `min 20 / max 60` → `min 12 / max 85`；运行时夹取 `15–75` → `12–85`（两处）。夹取范围与滑块量程对齐，避免"滑块能拖但值被夹住、视觉无变化"。

3. **取景系数**：`framingDistance()` 的系数 `1.12` → **`0.74`**，并保留 `?framek=` / `window.__FRAME_K` 覆盖入口便于日后实测调参。
   - 原因：1.12 是几何契约落地时为"方阵绝不出画"取的保守值，实测主体只占画面**宽 16.2% / 高 35%**，在 1440px 下偏小、氛围被背景吞掉。
   - 该系数是**除数关系**（距离 ∝ 系数），因此调小才会让主体变大——首次尝试改成 1.45 反而把主体推得更小，已纠正。
   - 定为 0.74 的依据是实测线性关系：主体占比与系数成反比（k=1.45→35%、1.20→42%、1.05→48%、0.95→54%、0.88→58%），方阵偏宽所以**高度先触边**，按高度约 69% 反解得到 0.74。

## 验证结果

- **默认在场**：`contentMode=avatar`、`avatarDist=all`、`selectedAvatar=cloud`、16/16 单元 `contentCount=1`；抽 4 个单元检查贴图非透明像素，**4/4 已绘制**（不是空白脸）；面板可见、模式按钮激活态正确。页面错误 0。
- **FOV**：滑块 `min=12 / max=85`，实际相机 `fov=30` 一致。
- **取景**（用投影到 NDC 实测主体占屏，不靠推算）：
  - 桌面 1440px：占宽 33.1% / 占高 **68.8%**（改前 16.2% / 35%）
  - 手机 390px：占宽 55.2% / 占高 **68.6%**，横向溢出 0
- **回归**：`idle-rest-state` 全绿（峰值 0.997、推动 0、交接残留 0.0000）；`arrival-stagger` 全绿（时间片 7 档跨度 0.780s、对角键序单调、角色格 16）；`LU_QUICK=1 main-view-geometry` → 相交组 0、`PASS`。

## 遗留问题与后续建议

- **FOV 滑块只变焦、不重新取景。** 实测 FOV 30 / 12 / 85 三档下相机距离恒为 20.54（旧系数），即拖 FOV 时主体大小随之变化，宽角端主体会被推得很小。本次只完成了"放宽范围"这一诉求，**没有**把它改成"改 FOV 时同步重新取景"——那会改变滑块语义（从"变焦"变成"不变焦"），是需要用户先确认的设计取舍。
- 取景系数从 1.12 改到 0.74 让主体占高接近 69%，上下边缘余量变小。当前在 4×4 / 单层下实拍未出画；**若后续排布改成更高层数或更大阵型，建议复测边缘余量**，`?framek=` 可直接用来对比。
- 默认角色是"全方阵群像"（`avatarDist: 'all'`，16 个同一角色）。它与面板默认激活项一致，避免了 UI 自相矛盾；若希望更强的主角感，可改为"中心单体"，但那样方阵会退为配角——属于审美取舍，未擅自更改。
- 仍未提交、未发布。
