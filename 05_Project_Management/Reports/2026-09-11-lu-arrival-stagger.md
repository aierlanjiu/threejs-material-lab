# 入场错时：让方阵"一站一站地到来"，并让角色排在第一位

Agent: 大江南（DSH 会话）· 2026-09-11

## 背景与判断依据

承接静息待机态。待机态解决了"没人操作时装置也是活的"，但**入场那一刻**仍然是一次性同时发生：初建时所有单元在同一帧从中心长出，读起来是"融化"而不是"到来"。

在"个性化氛围装置"的定位下，入场是唯一一个必须兑现"震撼"的瞬间（在场靠持续不出戏，震撼靠单点发生一次），而这个瞬间当时没有被当作一次演出对待。同时，个性化资产（8 款活体角色）仍埋在检查器第三层——用户在"中心单体"排布下本可以让自己的角色成为全场主语，但那个动作没有任何入场分量。

## 关键变更

`index.html`（与工程副本 `threejs_material_lab/index.html` 哈希一致）

- 每个新建单元带 `userData.arrival = { at, ready }`，主循环在到点前不推进该单元位姿、不写入可见尺寸，因此它保持不可见；到点后由既有插值系统平滑长到位。
- 错时键使用**对角坐标** `(x + y) / (pitch·√2)`（与波形同源的 1-Lipschitz 坐标），而不是径向距离。原因：4×4 方阵里大量格子到中心距离相同，径向键区分度不足（实测跨度只有 0.125s，肉眼读不出顺序）；对角坐标在方阵上均匀分层，扫掠方向也正是矩阵最惯用的"翻页"方向。实测时间片跨度 **0.78s**，跨 7 档。
- **刻意不判断 `oldPose`**：矩阵重建时 `previous` 总是有值，按 `oldPose` 门控会让入场永远不发生（旧位姿被整段继承——这是首版实现真正的失效原因）。真正的"复用"走 `reusable` 分支并直接 `continue`，所以"走到这里"本身即等价于"这是新单元"。
- **内容优先按"密度"而非"这一格有没有内容"判断**：`shouldRenderContent` 在材质模式下默认就是 `true`，直接拿它做条件会让所有格子挤在同一拍、错时完全失效（这是第二处失效原因）。改为构建结束后统计内容单元占比，只有内容稀疏（≤25%，即中心单体 / 巨像拼合 / 单张图片）时，才把承载内容的单元提前半个档次（`state.time + 0.02`，早于最早的 0.06 档）。
- 复用单元显式标记 `arrival.ready = true`，否则它会带着上一轮的 `arrival` 永远停在不可见状态。

## 验证结果

- **新增** `test/lu/arrival-stagger.test.js`（CDP 虚拟时钟）：
  - 对角键序 → 时间片序**单调成立**（首 key=-2.12 delay=0.06 → 末 key=+2.12 delay=0.84）。
  - 时间片 7 档、跨度 0.780s，足以读出顺序。
  - 无陈旧 `ready` 残留（重建后新单元不会一出生就可见），全部单元最终到位。
  - 入场完成后避让求解器推动 **0 对**（且求解器确认处于工作状态 59/60 帧，不是被跳过）。
  - 页面错误 0。
- **角色优先（稀疏模式）**：切到"角色 + 中心单体"后实测前三个到点单元为 `delay=0.02 content=true` → `0.06 content=false` → `0.0823 content=false`，**角色严格第一**。
- **入场实际发生**：真实时钟下触发整体重建后首帧 `到点=0/16、尺寸全为 0.001`，随后全部长到 1.000。
- **回归**：`test/lu/idle-rest-state.test.js` 全绿（峰值 0.996、推动 0、交接残留 0.0000）；`LU_QUICK=1 node test/lu/main-view-geometry.test.js` → 相交组 0、`PASS`。

## 发现的问题与解决方案

| 问题 | 根因 | 处理 |
| --- | --- | --- |
| 主循环第二帧即崩（`ReferenceError: arrived is not defined`），`state.time` 冻在 0.017 | 在第一个 forEach 里声明的 `arrived` 被用于第二个 forEach，作用域不共享 | 在各自循环内独立判定 `uData.arrival.ready` |
| 入场逻辑从未触发 | `previous[slotIdx]` 总是存在，旧位姿被整段继承 | 去掉 `oldPose` 门控，依靠"走到 else 分支即为新单元"这一事实 |
| 错时全部挤在同一时间片 | `shouldRenderContent` 在材质模式下默认为 `true` | 改按内容密度判断，仅稀疏模式做优先 |
| 径向键跨度只有 0.125s，读不出顺序 | 方阵对称导致大量格子距离相同 | 改用对角坐标，跨度提升到 0.78s |
| 角色与角落同时到达 | 对角扫掠下中心格与部分角落对角键相等 | 稀疏模式下内容单元再提前半个档次 |
| 复现困难：虚拟时钟一帧可跨 0.8s，逐帧采样看不到中间态 | CDP `advance` 策略的时间步不均匀 | 主判据改为断言"入场时间表"这一确定性事实，而非"某帧看到了什么" |

## 遗留问题与后续建议

- 入场是**首次构建与整体重建**才播的；复用池重排（用户拖材质滑杆）刻意不重播，避免反复打断。如果希望拖滑块时也有入场感，需要另设更轻的反馈，不要复用这条通道。
- 两个静态契约测试（`arrival-stagger`、`idle-rest-state`）承载的是当前的设计意图。若后续调整入场手感，请连同断言与注释一起更新，不要只改常量。
- 入场错时与静息待机态目前是两条独立通道，尚未联动。理想形态是"方阵长齐 → 整体转入呼吸"，目前靠时间上自然衔接（入场约 1.6s 收尾，静息包络时间常数约 1.8s），未做显式编排。
- 另需注意：`test/lu/main-view-geometry.test.js` 默认指向 `127.0.0.1:8091`，跑回归需显式传 `LU_URL`。
- 本轮未提交、未发布。
